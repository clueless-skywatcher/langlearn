# The printed book

`scripts/generate-latex.ts` turns a course pack into one LaTeX book: the rules
as numbered paragraphs, the vocabulary, the drills as an examination paper, and
the answers as an appendix. This file records how that book is set and the rules
the generator holds itself to.

```
./node_modules/.bin/tsx scripts/generate-latex.ts de --out build/german.tex
```

`build/latex/<course>.tex` is the default target; `--out` overrides it.

## The files

The book is a master file and one file per chapter beside it:

```
build/german.tex              the master: preamble, front matter, the includes
build/chapters/01-de-01.tex   one chapter
build/chapters/02-de-02.tex
...
build/chapters/11-answers.tex the appendix
```

The master carries the whole preamble, the title page, the front matter, the
`\part` headings and an ordered `\include` for each chapter; the chapters carry
nothing but their own content. Compile the master from `build/`, and compile one
chapter at a time by adding `\includeonly{chapters/03-de-03}` to the master —
`\include` keeps the page numbers and cross-references of the parts you leave
out, which is the reason the chapters are `\include`d rather than `\input`.

Each chapter file opens with a header naming its place in the sequence and the
files either side of it:

```latex
% Nouns II — The Plural
% Part 3 of 11 of the german.tex book.
% previous: chapters/02-de-02.tex
% next:     chapters/04-de-04.tex
% Generated by scripts/generate-latex.ts. Do not edit by hand.
% Included by german.tex; not a document on its own.
```

The chain is written as those pointers rather than as each file pulling in the
next. `\include` cannot nest, so a file cannot `\include` its successor at all;
`\input` can, but chaining with it would bury the order of the book inside the
chapters, break `\includeonly`, and leave the master unable to say what it
contains. The ordered list in the master is the same chain, made visible.

A chapter file is not a document: it has no preamble and no `\begin{document}`,
and will not compile on its own.

**The `.tex` is generated. Do not edit it by hand.** Its first three lines say
so, and every change made in it is lost at the next run. A change to the book is
a change to `scripts/generate-latex.ts`, or to the content under `content/<id>/`.

There is no LaTeX toolchain in this checkout — `pdflatex`, `xelatex` and
`lualatex` are all absent — so the generator's output is checked structurally
rather than by compiling. Anything that would only show up in a PDF is worth
saying out loud in review.

## Engines

Either engine builds the book, and the preamble branches on `\ifPDFTeX`:

- **pdflatex** takes the phonetic characters from `tipa` (`T3,T1` font
  encoding) and the text from Latin Modern.
- **xelatex / lualatex** load Latin Modern through `fontspec` and take the
  phonetic characters from a `DejaVuSerif` fallback declared as `\ipafont`.

## Page and type

| | |
|---|---|
| class | `book`, **12pt**, a4paper, twoside, openright |
| geometry | inner 27mm, outer 22mm, top 25mm, bottom 27mm |
| headers | `fancyhdr`; running section verso, chapter recto, `Page n` centred |
| a blank verso | truly blank — no rule, no number (`\cleardoublepage` is redefined) |
| depth | `tocdepth` 1, `secnumdepth` 2 |
| bottoms | `\raggedbottom`, and `\emergencystretch` 2em |

The last of those is deliberate: no German hyphenation patterns are loaded, so a
line of compounds is allowed to stretch rather than to overflow the measure.

## Characters beyond ASCII

Every non-ASCII character the content uses is declared twice — once in the
generator's `IPA` / `MATHS` / `KNOWN_UNICODE` tables, once in the preamble it
emits — and `checkUnicode` throws on any character that is in neither. A new
phonetic symbol therefore means two edits and never one. The error names the
file, the codepoint and the string it was found in.

## The content dialect

Content markdown is `**bold**`, `*italic*` and `` `code` `` and nothing else
(`lib/markdown.tsx` is the same dialect). A run of two or more underscores is
the gap of a fill-in-the-blank stem and becomes `\gap{}`. `¶42` becomes
`\rref{42}`, a hyperlink to that paragraph — but see **Questions** below for
where it may not appear.

## Rules

```latex
\rulehead{42}{The heading}   % P42. The heading. <statement runs on>
\begin{examples} \ex{target}{gloss} \exn{target}{gloss}{note} \end{examples}
\begin{paradigm}{caption} ... \end{paradigm}
\rulenote{a footnote}
```

A rule is a numbered paragraph in the manner of the grammar the courses follow:
the number and heading in bold, the statement run on from it, then the examples
indented under it.

## Drills

The paper is set in **two columns throughout** — `multicols`, `\small`, 20pt
gutter, `\raggedcolumns` — and reading passages are set in those columns like
everything else. A chapter's drills are one object on the page rather than two
settings alternating down it.

Questions are numbered from 1 within the chapter, continuously across the format
groups, so that a number names one question of that chapter. `\@beginparpenalty`
is raised so a stem never ends a column with its options at the head of the next.

| | |
|---|---|
| `questions` | the numbered list of questions |
| `choices` | the options, labelled `(A)`–`(D)` |
| `passage` | a reading passage, indented 0.8em to sit in a column |
| `\glosses{…}` | the passage's glossary, run together small |
| `\unit{…}` | an integer question's unit |
| `\pto` | the arrow of a matching pairing, `P→2` |
| `\qtype{…}` | a format tag on a comprehension child |

### Dialogue

A turn of dialogue is set as **the speaker's name in bold, then a colon**:

```
ANNA. Guten Tag!        ->    \textbf{ANNA}: Guten Tag!
HERR BECKER. Guten Tag.  ->   \textbf{HERR BECKER}: Guten Tag.
```

The content writes the name in capitals followed by a full stop, which is what
`content/validate.ts` requires of a passage with spoken turns; the generator
converts the stop to a colon and bolds the name. An all-capitals line with no
stop after it — a headline inside a passage, `ZIMMER FREI IN BREMEN` — is not a
turn and is left alone.

### Questions may not point at the material

A question tests the language, never this course's exposition (CLAUDE.md §2). So
**no reference to the material reaches a stem, an option, a matching column or
an integer's unit** — not a ¶ number, and not prose that names a rule, a
section, a chapter or something said earlier.

`texQ()` enforces the mechanical half: it strips `¶42`, `(¶42)` and `(see ¶42)`
from all four, and pushes a warning naming the question so the content can be
fixed at the source. The prose half is the author's job — an option reading
*"X is an exception to a rule that Y keeps"* passes `texQ` and is still wrong;
it belongs as *"X is irregular where Y is regular"*, which is a claim about
German.

¶ references stay welcome in rules, paradigm captions, footnotes and
explanations, every one of which the learner reads after the answer is in.

### A comprehension child names its format only when it must

The format groups carry a heading that names their format, so an item inside one
needs no tag. Inside a passage the formats are mixed, and the child says which
it is **only where it is not a single correct option**:

- `multi` → `\qtype{Multiple options correct}`
- `integer` → `\qtype{Integer answer}`
- `single`, `matching` → nothing

## Answers

The appendix repeats each question so that it can be read without the chapter
open beside it. One entry, in order:

```
<n>. <the stem, exactly as the paper set it>
     (A) … (B) … (C) … (D) …          % the options, if the format has any
     Answer: (C)  <the correct option>
     <the explanation, on its own line>
```

`\begin{answerentry}{n}{stem}` opens it, `\ansline{…}` is the answer line, and
the explanation follows as an ordinary paragraph before `\end{answerentry}`. The
entry is a list rather than a minipage so that a long one breaks across pages.

The appendix is set like the paper it answers: each chapter's `\section` heading
runs across the measure, and its entries sit in **two columns** under it, in the
same `\small` `multicols` setting the drills use.

What the answer line holds, by format:

| format | answer line | options shown |
|---|---|---|
| `single` | `(C)` and the option's text | all four |
| `multi` | every correct letter with its text, `;`-separated | all four |
| `integer` | the number | none |
| `matching` | the letter and its pairing, `P→3, Q→1, …` | the four pairings |

A comprehension block prints its title, and its translation where it has one,
before its children's entries.

## Sources

`sourcelist` is the bibliography of a chapter; `loci` nests under an entry the
places that work is cited for. A chapter can lean on one grammar twenty times,
and run together in a single parenthesis those references are unreadable, so
each keeps its own line.
